## 1. 第 8 步：待归位检测

### 1.1 一处设计改动：**不加 `PACKAGE_ADDED` 广播接收器**

原计划是静态注册 receiver 监听 `PACKAGE_ADDED` / `PACKAGE_REMOVED`。但按我们既定原则
（`notes/15` §8）：**不做静默重排、也不发通知** —— 用户不打开 app 时，接收器什么也做不了。

既然提示只出现在 app 内，**按需比对**就够了，而且少一个"广播没收到就静默失效"的故障面。

### 1.2 做法

- 每次 `openFile` 成功生成布局后，把当时的应用集合记为 `knownApps`（**那份布局已含全部应用，按定义就是已归位**）
- 打开 UI 时，对比"当前应用集合"与 `knownApps` → 产出 `added` / `removed`
- 首次运行（无 `knownApps`）直接记为已知，**避免"全部应用都是新装的"这种误报**
- UI：概览卡顶部一条横幅 + 「去应用（归位）」按钮

### 1.3 实测（用「卸载→导入→重装 Shizuku」制造真实增删）

| 步骤 | `pending` |
|---|---|
| 卸载 Shizuku（未导入） | `移除=['moe.shizuku.privileged.api']` ✅ |
| 重装同包名 | `新增=[] 移除=[]` —— **正确**：布局里本来就有它 |
| 卸载 → **触发一次导入** → 重装 | `新增=['Shizuku']` ✅ |
| 卸载 → 导入后保持卸载 | `新增=[] 移除=[]` —— **正确**：卸载时它已不在已知集合里 |

> 后两行说明这套逻辑的语义是**"与上次归位时的集合比"**，而不是"与设备历史比"。
> 这正是我们想要的：**应用没动过就不该报"待归位"**。

## 2. 第 9 步：配置导入导出

### 2.1 一处设计取舍：**用剪贴板，不用文件**

分享文件需要 `FileProvider`（要有 `res/xml/file_paths.xml`），而本项目是**不用 Gradle 手搓构建**的、
**目前没有任何资源目录**。配置 JSON 只有 300 字节左右。

→ **导出 = 复制到剪贴板；导入 = 从剪贴板读**。零依赖、零权限，粘贴到聊天/笔记里就能备份或分享。

### 2.2 实测

```
导出 → 318 字节 JSON：{"dockMode":"auto","folderSort":"name","screenStrategy":"balanced",
                       "manualDock":[...],"overrides":{},"customFolders":[...]}
```
改一份（`dockMode=usage, screenStrategy=usage`）再导入：

```
content call --method IMPORT_CONFIG --arg "$(cat cfg.json)"
→ RESULT=OK
导入后：dockMode=usage screenStrategy=usage manualDock=[settings, maps] ✅
```

> `applyJson` 的逻辑其实在**第 7 步的方案切换**里已经验证过了 —— 导入导出复用的就是它。
