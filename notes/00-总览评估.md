## 一、项目目标

**原始需求**：安卓端有没有"批量移动图标 / 自动排列桌面图标"的工具？

**演进路径**：

1. 跨平台调研（Windows + 安卓）→ 结论：Windows 已有成熟项目（DeskBox 等），安卓端该方向**几乎空白**
2. 方向转向安卓端（桌面端不重复造轮子）
3. 收集参考实现（4 个仓库）
4. 逐个精读源码（5 篇笔记）
5. **当前节点：PoC 起步前**

**核心待解问题**：安卓没有公开 API 让第三方重排桌面图标——如何实现"批量移动 / 自动排列"？

## 三、学习成果总览

| # | 项目 | 最有价值的结论 |
|---|---|---|
| 01 | android-app-organizer | **执行层用 UIAutomator2（adb），不是无障碍**；「launcher.db 快照做规划 + UI 自动化做执行」混合；长按 **1.45 s** 进编辑模式 + 分段曲线拖拽 + 抖动悬停建文件夹；12 个手势时序参数 |
| 02 | android-folderautomanager | **路径④ 的完整实现**；8 级分类优先级链；**`ApplicationInfo.category`（Play Store 官方分类）是免费离线信号**；厂商前缀规则；DeepSeek fallback（批量 15 + 双层缓存 + 10s 超时 + 失败不写缓存） |
| 03 | novalaunchereditor | `.novabackup` = **重命名 zip（SQLite + XML）**；favorites 字段语义（`container` -100/-101、`screen=0` 表示在文件夹内）；**探测式 schema 兼容**（`hasTable`/`hasColumn`） |
| 04 | lawnchair / Launcher3 | 布局库是 Launcher3 的 **`launcher.db`**（不是 `app.lawnchair.data.AppDatabase`）；**favorites 表 19 列权威定义**（SCHEMA_VERSION=32）+ container 常量全表 |
| 05 | Launcher3 布局通道 | **第五条路径**：布局用 **XML**，经 **BlobStore / ContentProvider** 传递，由 `launcher3.layout.provider` 触发；**adb 即可，不需 root** |

## 四、五条技术路径评估

| 路径 | 参考实现 | 粒度 | 权限门槛 | 速度 | 适用范围 | 风险 | 推荐度 |
|---|---|---|---|---|---|---|---|
| ① UI 模拟拖拽 | android-app-organizer | 单图标 | 无（adb / 无障碍） | 慢 | **广（任何 launcher）** | 时序脆弱、需逐机型调 | ★★★ |
| ② 直写 `launcher.db` | lawnchair/Launcher3 | 整库 | **root / Shizuku** | 瞬时 | Launcher3 系 | schema 演进、被覆盖 | ★★ |
| ③ 解析备份文件 | novalaunchereditor | 只读 | 无 | — | 仅对应 launcher | 只读，不能写 | ★ |
| ④ 自建 launcher | android-folderautomanager | 整体 | 用户换桌面 | — | 无限制 | 改变用户习惯 | ★★ |
| **⑤ 官方布局通道** | lawnchair/Launcher3 | **整份布局** | **adb / root（写 Secure Settings）** | **瞬时** | **仅 Launcher3 系** | **清空重建数据库** | ★★★★ |

**关键判断**：

- **⑤ 是技术上限最高的**——整份布局一次性导入，且走官方解析路径（不怕 schema 演进）；但**只对 Launcher3 系有效，Nova 无效**，且导入会清空重建。
- **① 是覆盖面最广的**——任何 launcher 都能用，代价是慢和脆。
- **② 介于两者之间**——Launcher3 系可用、瞬时，但需 Shizuku/root 且风险最高。
- **③④ 更适合作为"知识来源"和"产品形态选项"**，不是主路径。

## 五、关键认知沉淀（6 条）

1. **LLM 不是必需的**：两个项目都把 LLM 放在最低优先级（规则兜底 → 关键词 → LLM），且失败自动回退。
2. **`favorites` schema 三仓库同构**：Nova / Lawnchair / 系统 Launcher3 共享 AOSP schema → 路径②③ 可复用同一套字段知识。
3. **`ApplicationInfo.category`（Play Store 官方分类）是免费离线信号**，应作为分类**首选**。
4. **Launcher3 有官方布局导入/导出通道**（第五条路径），可能是不 root 改布局的正路。
5. **UI 拖拽的前提是"长按进编辑模式"**（约 1.45 s），否则拖不动图标。
6. **厂商前缀分类**（`com.google.*` → Google 文件夹）是廉价高效的启发式，但要做"单应用文件夹降级"。

## 六、风险与障碍

| 类别 | 风险 | 应对 |
|---|---|---|
| 环境 | 目录 rename / 大目录删除被系统限制 | 手动清理遗留目录 |
| 技术 | ⑤ 导入会 `createEmptyDB + forceReload`，失败可能丢布局 | **先备份**；PoC 前导出一次现有布局 |
| 技术 | ⑤ 仅 Launcher3 系有效，Nova / 厂商 ROM 未知 | 需实测；用 ① 兜底 |
| 技术 | ① 的时序参数需逐机型调 | 参数化配置（参考 android-app-organizer） |
| 数据 | 分类依赖应用名/包名/官方 category，包名无意义的 App 会误判 | 保留"人工纠正 + 相似应用批量建议"（参考 02 的 `findSimilarUnclassifiedApps`） |
| 法律 | novalaunchereditor **无 License** | 仅参考思路，不复制代码 |

## 八、决策建议

1. **主攻 ⑤**（Launcher3 官方布局通道）：技术上限最高、最"正规"、无需 root。
2. **① 作为兜底**：覆盖非 Launcher3 系 launcher（Nova、厂商 ROM）。
3. **分类器**直接照搬 02 的思路：`ApplicationInfo.category` 首选 → 内置映射表 → 厂商规则 → 关键词 → LLM（可选）。
4. **PoC 只做最小闭环**：先证明"能通过官方通道导入一份布局"，不要一开始就做完整产品。
5. **先备份**：⑤ 会清空重建数据库 —— 但**用模拟器就绕开了这个问题**（搞坏直接删掉重建），不需要备份真机。

## 附：关于「导出现有布局」的澄清

上一版 P0 写的"导出一份现有布局做备份"太笼统，这里说清楚——**取决于目标 launcher**：

| 目标 launcher | 有无现成导出手段 |
|---|---|
| **Nova Launcher** | ✅ **自带**：设置 → Backup，导出 `.novabackup`（即笔记 03 解析的格式） |
| **Lawnchair** | ✅ **自带**：设置里有备份/恢复 |
| **系统 Launcher3 / Pixel Launcher** | ❌ **无用户可见的备份按钮** —— 这正是"根本没有相应工具"的原因 |
| 厂商 ROM（小米/华为） | ⚠️ 多数在"设置 → 备份"或云服务里有桌面布局备份，需实测 |

**结论**：对**系统 launcher**，确实没有现成工具能导出布局 —— 要导就得自己实现（读 `launcher.db`，或用笔记 05 的官方 `exportModelDbAsXml` 思路）。

**但采用模拟器方案后，这个需求直接消失**：模拟器是干净环境，搞坏就删掉重建，无需备份。

## 附二：模拟器环境的现实约束（已实测本机）

| 项 | 现状 |
|---|---|
| AVD | 已有 `GalgameApi26`（**API 26 = Android 8.0**） |
| emulator | ✅ `C:\Users\Doro\AppData\Local\Android\Sdk\emulator\emulator.exe` |
| avdmanager | ✅ `...\cmdline-tools\latest\bin\avdmanager.bat` |
| system-images | 仅 `android-26` |

**关键约束**：**API 26 太老**。
- `ApplicationInfo.category` 需要 **API 26+** → 勉强够用 ✅
- **但 Launcher3 的官方布局通道（路径⑤）是 2024 年 AOSP 才引入的**（`LayoutImportExportHelper.kt` 版权年份 2024，对应 Android 14/15）→ **API 26 上不存在** ❌

**所以要验证路径⑤，必须新建 API 34/35 的 AVD**（需下载 system-image，体积较大）。
