## 0. 前提判断（决定整个计划的形状）

要做 7 个功能，但**真正的难点不是功能本身，而是地基**。

重构前 `LayoutProvider.java` 1248 行，同时扛着 6 件事：ContentProvider 契约 + 应用枚举 + 分类 +
规划 + XML 渲染 + JSON 序列化 + 9 个 `call()` 方法；配置还散在 4 种 key 前缀里。

而要加的 7 个功能里，**有 5 个都会碰配置**：Profile 本质是"多套配置"、Dock 是配置、
首屏策略是配置、导入导出是配置序列化、快照是配置的历史版本。

→ **所以第 1 步必须是重构**：把「配置」和「规划」从 provider 里抽出来。

## 3. 第 1 步：重构 ✅

### 3.1 新架构

```
LayoutProvider.java   ← 只做 ContentProvider 契约（openFile / call / query）+ UI 的 planJson
LayoutPlanner.java    ← 纯规划：① 枚举 → ② 分类 → ③ 成组 → ④ 占格 → ⑤ 渲染 XML
AppConfig.java        ← 全部配置收口（调试开关 / 覆盖 / 手动分组 / 网格）
MainActivity.java     ← WebView 壳 + JS 桥（含 Shizuku）
```

依赖方向单向：`LayoutProvider → LayoutPlanner → AppConfig`，无环。

### 3.2 `AppConfig` 收口了什么

| 原位置 | 现位置 |
|---|---|
| `Config`（读 `poc-config.txt`） | `AppConfig` 的 `widgets/searchWidget/spread/repeat` |
| `overrideOf()` / `isExcluded()`（读 `ov:`） | `AppConfig.overrideBucket()` / `isExcluded()` |
| `loadCustomFolders()`（读 `cf:`） | `AppConfig.customFolders()` |
| `openFile` 里直接写 `gw/gh/hs` | `AppConfig.saveGrid()` / `gridKnown` |

**存储格式暂未改动**（仍是 `ov:` / `cf:` / 平铺 key），以保证行为零变化。
JSON 化 + Profile 前缀留到第 7 步做（届时才需要迁移，迁移前会先整份 dump 备份）。

### 3.3 验证

| 验证项 | 结果 |
|---|---|
| 基线 XML 逐字节比对（full / merge） | ✅ **MD5 完全相同** |
| `openFile` 端到端（基线比对**没覆盖**这条路径） | ✅ `收到布局请求` → `网格 4x6` → 合并模式规划 → **overlap = 0** |
| 落库核对（pull `launcher.db` + sqlite3） | ✅ 24 行；文件夹 = `我的分组 / 效率 / 工具 / 其他` |

> ⚠️ 这一步特意单独做了 `openFile` 的端到端验证 —— 因为 golden 比对走的是 `PLAN_JSON`，
> 而重构改动了 `openFile` 的网格保存与文件写入逻辑，**只看 golden 会漏掉**。

## 5. 关键设计要点（后续步骤会用到）

### 5.1 使用频率（第 2–3 步）

- `UsageStatsManager.queryUsageStats(INTERVAL_DAILY, now-30d, now)`
- score = 近 7 天时长 × 1.0 + 近 8–30 天时长 × 0.4
- **三层降级**：有权限→真实数据；无权限→顶部引导条（跳 `ACTION_USAGE_ACCESS_SETTINGS`）；
  有权限但全 0（新机/模拟器）→ 静默回退现有逻辑
- 缓存：内存 + `usage-cache.json`，TTL 30 分钟（查询耗时 200–800ms）
- **验证手段**：模拟器无使用数据 → 用 `adb shell am start` **反复启动几个应用制造真实记录**

### 5.2 变更 Diff（第 4 步）

复用 `LayoutPlanner.CurrentLayout.parse()` 解析 `last-generated.xml` 当基线 → 对比出
**新增 / 移除 / 移动 / 保留** 四类。UI 要写明"基线是本应用上次生成的布局，非 launcher 真实布局"。

### 5.3 快照（第 6 步）

每次生成后复制到 `snapshots/<ts>.xml`，保留最近 5 份；回滚 = 写回 `last-generated.xml` 再走一次正常应用。

### 5.4 Profile（第 7 步）

`cfg:<profileId>` → 整个 AppConfig 的 JSON。切换方案 = 换整套配置，需重新点应用才生效。
**迁移**：首次启动把旧的 `ov:` / `cf:` / 平铺 key 收进 `cfg:default`，迁移前 dump 到 `migrate-backup.json`。

### 5.5 新装应用归位（第 8 步）

静态注册 receiver 收 `PACKAGE_ADDED` / `PACKAGE_REMOVED`（`PACKAGE_ADDED` 是 Android 8+
隐式广播限制的**例外**，可静态注册；注意过滤 `EXTRA_REPLACING`）。
**坚持不做静默重排** —— 只做"提示 + 一键归位"。
