# 11 · UI（P6）：WebView 界面 ✅

> 执行日期：2026-10-01
> 结论：**给项目加上了可交互界面**。原本只有一个「哑」ContentProvider，现在是一个**带 UI 的 app**：
> 展示应用清单与分类、**可视化桌面预览**、生成 XML、并提供应用入口。
> 产物：`poc/src/com/example/layoutprovider/MainActivity.java`、`poc/assets/ui.html`、截图 `poc/artifacts/ui-*.png`

---

## 1. 技术选型：为什么用 WebView

整个 APK 是**不用 Gradle/AGP 手搓**的（`aapt2 + d8 + apksigner`，见笔记 07）。这意味着：

| 方案 | 代价 |
|---|---|
| 原生 View + Material/RecyclerView | 要引入 AndroidX，手搓构建链下**极难**（AAR、资源合并、依赖树） |
| **WebView + 本地 HTML** | **零依赖**，`assets/` 本来就被 `aapt2 -A` 打包；界面用 HTML/CSS 写，桌面预览直接用 CSS Grid 画 |

选 WebView 的另一个好处：**桌面网格预览**用 CSS Grid 几行就画出来了，用原生自定义 View 得写不少测量/布局代码。

APK 体积：**16.8 KB → 33.3 KB**（+16 KB，几乎全是 `ui.html`）。

## 2. 架构

```
MainActivity (Activity)
  └─ WebView ── loadUrl("file:///android_asset/ui.html")
       │
       └─ addJavascriptInterface(bridge, "Android")   ← 页面里的 window.Android.*
            ├─ getPlan()    → ContentResolver.call(自己, "PLAN_JSON")  → JSON 字符串
            ├─ apply()      → ContentResolver.call(自己, "APPLY")      → 结果文本
            ├─ adbCommand() → 返回免 root 的 adb 命令
            └─ copy(text)   → 写剪贴板
```

**关键设计**：UI **不自己算布局**，而是回头调**同一个 app 里的 provider** 的 `PLAN_JSON`。
这样「预览」和「真正导入给 launcher 的 XML」走的是**同一份规划代码**（`buildPlan()` + `render()`），
**不会出现预览与实际不一致**。

新增的两个 provider 方法（`LayoutProvider.call()`）：

| method | 作用 |
|---|---|
| `PLAN_JSON` | 返回规划快照 JSON（应用清单 + 分类 + 去向 + 占位 + XML） |
| `APPLY` | 借 `su` 写 Secure Settings（普通 app 自身没权限） |

另外 `openFile()` 现在会把 launcher 传来的 `gridWidth/gridHeight/hotseatSize` **记进 SharedPreferences**，
供 UI 预览使用（否则 UI 不知道当前设备的网格）。

## 3. 界面分区（5 块）

| # | 区域 | 内容 |
|---|---|---|
| 1 | **概览** | launcher 包名 / 网格 `4×6` / dock 数 / 应用总数 / 桌面槽位 / 占用屏幕；以及**合并模式**与基线来源 |
| 2 | **桌面预览** | 按 `screen` 分屏，用 CSS Grid 画出每一屏：文件夹（堆叠小方块）、图标、小组件；屏幕 0 第 0 行画成**斜纹「系统占用」** |
| 3 | **应用清单** | 每行：应用名 + 包名 / 分类 chip / 去向 chip（`📁 效率`、`Dock`、`桌面`、`未排入`） |
| 4 | **应用到桌面** | adb 命令（一键复制）、「尝试直接应用（需 root）」按钮、**生效条件与风险提示** |
| 5 | **布局 XML** | 折叠区，可展开查看/复制完整 `<workspace>` XML |

## 4. 「应用」这一步的权限现实（**必须让用户知道**）

| 路径 | 可行性 | UI 表现 |
|---|---|---|
| 本 app 自己写 Secure Settings | ❌ 没有 `WRITE_SECURE_SETTINGS` | 不可用 |
| 借 `su` 写（root 设备） | ✅ | 「尝试直接应用」按钮；**非 root 设备会安全失败** |
| 用户手工执行 adb 命令 | ✅ | 命令框 + 复制按钮 |

实测（模拟器未 root）：

```
[APPLY] 无法执行 su：java.io.IOException: Cannot run program "su": error=13, Permission denied
        （设备未 root，请改用下面的 adb 命令）
```

**且失败时不会误改设置**（已核对 `settings get secure launcher3.layout.provider` 未变）。

UI 里同时明确写了**生效条件**：写入 Secure Settings 后还需让 launcher **重建桌面数据库**
（`createEmptyDB`）才会来读布局，而**这会清空现有桌面布局** —— 必须让用户先确认。

## 6. 复现

```bash
cd poc && bash build.sh
adb -s emulator-5554 install -r poc-layoutprovider.apk
adb -s emulator-5554 shell am start -n com.example.layoutprovider/.MainActivity
```

调试 UI 数据（不经过界面）：

```bash
adb shell "content call --uri content://com.example.layoutprovider --method PLAN_JSON"
adb shell "content call --uri content://com.example.layoutprovider --method APPLY"
```

## 7. 遗留 / 可改进

- **界面还不能改分类**：现在分类是只读展示。要做「用户手动调整分类 / 排除某应用」，
  需要把 `bucketOf()` 的规则外置成配置，并让 UI 能回写。
- **没有「一键走完」**：仍需用户自己触发 launcher 重建。若能引入 **Shizuku**，
  可把「写 Secure Settings + 触发重建」都自动化（Shizuku = shell 身份，**有** `WRITE_SECURE_SETTINGS`）。
  （注意：Shizuku **不能**帮我们读布局，见笔记 10。）
- **无应用图标**：为了保持手搓构建简单，UI 用**首字母色块**代替真实图标；
  要显示真实图标需从 `PackageManager` 取 `Drawable` 再转 base64 传给 WebView。

## 8. 第二轮增强（2026-10-02）：四项功能全部落地

### 8.1 ✅ 分类可编辑 / 应用可排除

**数据层**：用户覆盖存在 SharedPreferences（key = `ov:<包名>`，value = `"<分类>|0或1"`，末位 1 = 排除）。

- `bucketOf(e)` 先查覆盖，命中就用用户的分类；否则走 `bucketOfAuto(e)`（原自动规则）
- `buildPlan()` 开头先过滤掉被排除的应用（`plan.excluded` 计数）
- provider 新增 `SET_OVERRIDE`（改分类 / 排除）与 `CLEAR_OVERRIDES`（恢复自动分类）

**界面**：应用清单每行右侧是**分类下拉 + 排除开关**；改过的行会显示「已改」徽标，
被排除的行整体变灰并显示「已排除」。

**实测**（直接点界面上 Files 那行的开关）：

```
[SET_OVERRIDE] com.google.android.documentsui -> bucket=工具, excluded=true
```

界面随即重绘：Files 变灰、开关打开、概览出现「已排除 1 个应用」，
**「工具」文件夹从 3 个图标变成 2 个**（Clock + Settings）——排除真的作用到了规划结果上。

### 8.2 ✅ 一键应用（两条路 + 安全失败）

provider 新增 `APPLY_FULL`：`su -c` 依次执行
**写 Secure Settings → `pm clear <launcher>` → 回到桌面**，一步到位。

- **有 root**：一次点击完成全流程
- **无 root**：`su` 不可用 → **提前返回，不会执行后续任何命令**（实测 `APPLY_FULL` 返回
  `无法执行 su: ... Permission denied`，且已核对 Secure Settings 与 launcher 数据均未被改动）
- 界面同时给出可复制的 adb 命令，并明确写出**生效条件**与**「会清空现有桌面布局」的风险提示**

### 8.3 ✅ 真实应用图标

provider 在 `planJson()` 里为每个应用生成
`Drawable → 72×72 Bitmap → PNG → Base64` 的 `data:image/png;base64,…` 串，
界面直接 `<img src>` 显示；文件夹预览与 Dock 也复用同一份图标（按应用名索引）。

APK 体积：33.3 KB → **37.4 KB**（图标在运行时生成，不进包体）。

### 8.4 ✅ 深色模式

WebView 的 `prefers-color-scheme` 在无主题资源的手搓 APK 里不可靠，
所以**由 Java 判定**：`MainActivity.getTheme()` 读 `Configuration.uiMode & UI_MODE_NIGHT_MASK`
→ JS 给 `<html>` 加 `.dark` 类 → CSS 变量整体切换。

实测：`cmd uimode night yes` 后重启界面，整站（卡片 / 网格 / 表格 / 下拉 / 开关）全部正确转为深色。

## 9. 仍然遗留

- **应用图标是运行时生成的**，页面首屏会稍慢（18 个 × base64）；后续可改为按需加载
- **分类下拉的候选是固定词表 + 现有桶**，不支持用户自定义新分类名
- **没有预览与真实导入的差异提示**（两者共用同一份代码，正常情况下不会不一致）
- 未在真机验证（本机真机未接）
